## M20 — My Vault: profile, family, policies and an optional passkey account (16 October 2026)

First milestone of the startup roadmap (`docs/PRODUCT-ROADMAP.md` §13, Phase 1). Everything ships on the ₹0 rollout stack: Cloudflare Workers Free, D1 Free, Turnstile, browser WebAuthn and WebCrypto. No new dependency, paid service, SMS/WhatsApp gateway or card-on-file.

**What the user gets.** `/vault/` (nav "My Vault") saves a profile (name, city, letter language), family members (relation, birth year, conditions) and policies (health/life/motor; insurer, catalogue plan or free-text plan name, policy number, sum insured, current start date, continuous-cover-since date, renewal date, covered members, UHID, current claim number, employer flag, room-rent rule, co-pay, consumables cover, health check-up limit, notes, default flag). Every generated letter on `/`, `/deductions/` and `/rejected/` now fills `[Your name]`, `[Policy number]`, `[Claim number]`, `[Policy / Claim number]` and `[UHID]` from the vault **at display time** (`src/lib/identity.ts` → `setupLetterDialog({insurerId})`), only for the policy matching the letter's insurer (or the chosen default when the insurer is unlisted); the dialog note changes to "Filled from your vault" and the My Vault hint disappears. A fresh clock pre-selects the vault's default health insurer. Each policy card shows derived facts: months of continuous cover, the 60-month Health moratorium (Ch. I 13) or the 36-month Section 45 shield reached/remaining, and days to renewal with the grace-period reminder when overdue.

**Plan catalogue.** `data/plans.json` holds 10 retail plans (HDFC ERGO my:Optima Secure, Niva Bupa ReAssure 2.0, Care Supreme, Star Comprehensive, Star Senior Citizens Red Carpet, Aditya Birla Activ One MAX, ICICI Lombard Elevate, Tata AIG MediCare Premier, New India Mediclaim, Bajaj Health Guard Platinum) with 65 sourced rules (room rent, co-pay, PED/specific/initial waits, consumables, health check-up), each carrying `source_url`, `verified_on` (2026-10-16) and a quoted `evidence` string from the insurer's CIS, wording, prospectus or product page; unverified rules are `null` and render as "not verified — check your CIS". `scripts/validate-data.mjs` fails the build if any stated rule lacks provenance. Choosing a plan shows the rules with source links and pre-fills only empty fields. Correction found during research: Care Supreme's base room category is "No limit"; Single Private AC is an optional modification.

**On-device parser.** `src/lib/policy-parser.ts` reads a schedule/CIS (via the existing `extractFile` PDF/OCR path) for insurer, catalogue plan, policy number (spaced groups allowed), UHID, sum insured (lakh/crore words), start/renewal/continuity dates (day-first), room rule, co-pay % and insured members with relations/birth years; it fills blanks only and reports what it could not find. Members found are added to the family list and ticked on the policy.

**Account and sync.** Registration: Turnstile → `/api/auth/register/options` (random account handle, resident key + user verification required, attestation none, `prf` extension requested) → `navigator.credentials.create` → `/api/auth/register/verify`. The Worker verifies WebAuthn itself (`worker/webauthn.ts`: bounded CBOR/COSE parsing, ES256 DER→raw conversion, RS256, rpIdHash/flags/counter checks; attestation statements are not trusted, which is equivalent to "none"). Login is usernameless (`allowCredentials: []`; the authenticator returns the account handle, which must match the credential's account). Sessions are 64-hex random tokens stored as SHA-256 in `sessions`, cookie `cc_session` HttpOnly/Secure/SameSite=Strict/Path=/api, 30 days. Challenges are single-use (`DELETE … RETURNING`), five minutes, hash-only. The vault key is generated in the browser (`vault-crypto.ts`), the vault is AES-256-GCM encrypted (version byte + IV + ciphertext + tag, ≤256 KiB) and `PUT /api/vault` carries the expected version; a stale version returns 409 and the page offers "Load the synced copy" or "Keep mine and overwrite". Cross-device unlock: when the authenticator supports the PRF extension, the key is HKDF-wrapped with the PRF output and stored on the credential row (opaque to the server) so a synced passkey unlocks a new device automatically; otherwise the user keeps a **recovery link** (`/vault/#recover=KEY`, key removed from the URL before anything else loads) shown as text and QR. `DELETE /api/auth/account` removes vault, sessions, credentials, challenges and user in one batch. Cases on the device are included in the synced vault and merged by id on other devices (`importCases`). Server: `migrations/0004_user_vaults.sql`, `worker/auth.ts`, `worker/webauthn.ts`, routes in `worker/app.ts`, hourly purge of expired challenges/sessions; quotas `auth_register 200/5`, `auth_login 1000/20`, `auth_session 10000/200`, `vault_read 5000/100`, `vault_write 2000/30`, `account_erase 100/5` (day/minute).

**Scope notes against the roadmap.** (1) The "short cross-device pairing code" became the recovery link + PRF unlock: a code would still need the key, and the link already carries it without any server storage. (2) The DigiLocker Requester adapter is not wired: it needs API Setu partner onboarding (free, but a founder action: client id/secret and an approved requester application). ## M22 — ClaimClock Voice: hands-free bilingual assistant with on-device tools (17 October 2026)

Third and last Phase 1 milestone (`docs/PRODUCT-ROADMAP.md` §2, §13). Still ₹0: the speech model and the chat model are the already-configured Groq free tier (`openai/gpt-oss-120b` plus `whisper-large-v3-turbo` on the same key), spoken replies use the browser's own `speechSynthesis`, verification is Turnstile, budgets are D1 counters. No new dependency, table, migration or paid service; nothing from a conversation is stored anywhere.

**What the user gets.** A "Talk" button on every page opens ClaimClock Voice. The first step names both processors from `/api/config` (speech and chat model) and lists exactly what leaves the device; the microphone is requested only after the box is ticked, and "Type instead" works without it. Then: a live orb/waveform, hands-free turn-taking (speech ends after 700 ms of silence, 25 s cap, pre-roll so the first syllable is not clipped), barge-in (talking over the assistant cancels its speech after 250 ms of sustained voice above a raised threshold, so playback echo cannot interrupt it), push-to-talk as a manual override, a typed input, the transcript, and **action cards** produced by eight tools that run in the browser on the user's own vault, cases, catalogue and simulators: `check_policy_benefit` (check-up eligibility and amount, room-upgrade impact, waiting periods and the moratorium, co-pay, pre/post window, sub-limits, consumables — each with the rule's source link), `recommend_or_compare_plans` (cited-rule comparison, structural family advice, link to `/compare/?plans=…`; never a recommendation or premium), `manage_claim_clock` (start the hospital clock, log a query/call/document event, record the decision — the hospital page adopts the change live), `audit_bill_deductions` (deterministic classifier over spoken lines), `draft_and_queue_action` (clock-lock, follow-up, GRO, delay-charge, rejection, hospital-desk and reconsideration letters, personalised from the vault, shown with copy / email / WhatsApp buttons), `save_user_policy` (insurer and plan resolved from speech — "Star", "Max Bupa", "New India", "Optima Secure" — members by relation, sum insured, dates; the policy number is never taken by voice), `check_renewal`, and `track_reimbursement` (answers honestly that the tracker ships with M26). Replies are one to three spoken sentences in the interface language (English or Devanagari Hindi); cards follow the language too.

**Boundary.** `worker/voice.ts` owns the system prompt (hard rules: no deadline, limit, amount, rule or contact from memory — only what a tool returns; information, not legal advice; never ask for or repeat names or numbers; one clarifying question instead of a guess) and the tool schemas, so a tampered client cannot add tools or soften the rules. The copilot envelope is strict: ≤16 messages, ≤1,500 characters each, ≤9,000 total, roles must form valid user → assistant(tool_calls) → tool round trips, unknown tools and system messages are rejected, and the context has **no field** for names, policy numbers, UHIDs or claim numbers (`validateContext`), with every free-text field pattern-redacted like `/api/explain`. Audio arrives as the raw recording (no base64 on the 10 ms CPU budget), is checked for consent header, language hint, declared type, size (1 KiB–600 KiB) and container signature (WebM/Ogg/MP4/WAV), and is forwarded as multipart; provider responses are size-bounded, reasoning fields are stripped, tool calls are validated and capped at four, and provider errors become generic 503s. Tool results are the model's only source of figures and carry `source_url`/`verified_on`; a drafted letter's body never goes back to the model (`tests/voice-agent.test.ts` asserts it). Budgets: `voice_transcribe` 300/day, 10/minute; `copilot` 150/day, 4/minute — the chat tier allows 8,000 tokens a minute and a compact call is ≈2,000 tokens. `public/_headers` now allows `microphone=(self)`.

**Scope notes against the roadmap.** (1) The "fast streaming" browser `SpeechRecognition` path is not used: it would add a second speech processor (Google, for Chrome) for interim captions only; one consented processor is the better privacy story, and the orb plus "Go ahead — I'm listening" cover the feedback. (2) Groq's Orpheus TTS is not used: 10 requests a minute on the free tier and English-only; browser voices are instant, free and cover `hi-IN`. (3) `track_reimbursement` returns `tracker_not_yet_available` with guidance rather than inventing a settlement deadline; `check_renewal` tells the model not to quote a grace period until M25 adds the sourced rule. (4) Family-member names are never spoken into the vault — `save_user_policy` creates members by relation ("Spouse") for renaming in My Vault. (5) Turnstile tokens are single-use, so the dialog pre-fetches the next `voice` and `copilot` tokens while the user is still talking; no voice-session table was added.

## M22.1 — Saathi: faster, warmer, better-looking voice companion; first paid option behind a flag (17 October 2026)

Founder feedback after M22: the agent was not convincing, the dialog did not look good, the assistant needed a proper name, model and provider names should not be printed in the UI, and — a policy change — paid services are acceptable where the free path clearly compromises the result, with the code staying open source. This revision answers all five.

**Name and manner.** The assistant is **Saathi** (साथी — "the one with you during the wait", matching "A clock on your side"). The system prompt now carries a persona (warm, calm, plain words; lead with the answer, then one next step or one question; confirm actions and point to the card; decline unrelated topics) on top of the unchanged hard rules. A user who speaks or types in Devanagari is answered in Hindi even on the English interface (`replyLanguage`). Provider and model names are gone from the dialog; the consent step names the *kind* of processing and links to the privacy page, which now reads the live provider names from `/api/config` and shows them there.

**Speed: streamed sentences.** `/api/copilot` streams server-sent events when the client asks for `text/event-stream`: each sentence is cut at a terminator followed by whitespace (so "₹3.5 lakh" never splits), redacted, and emitted as it completes; reasoning blocks never reach the client; chunked tool-call deltas are reassembled and shaped exactly as before; the final `done` event carries the full result; any provider irregularity becomes one generic `error` event. The browser speaks each sentence as it arrives and shows a live bubble, so speech starts within the first sentence instead of after the whole reply. Measured against the real provider through `completeStream`: tool call in 0.54 s, and on the answering round the first Hindi sentence at **0.25 s**, full reply at 0.28 s (the earlier design waited for the complete JSON before speaking).

**Look.** `VoiceCopilot.astro` is now a bottom sheet on phones (slides up, rounded top, mic and input pinned to the bottom, conversation scrolls between) and a centred card on desktop; a gradient orb that breathes when idle, ripples with the voice, turns a dashed ring while thinking and pulses while speaking; chat bubbles with a Saathi avatar; six suggestion chips on the empty state (bilingual, tapping sends them); a round mic button with "Tap to talk / Tap when you're done"; a hands-free switch; the launch pill reads "Saathi" with a gently pinging dot. The consent step is one greeting, one summary sentence and an expandable "What exactly leaves your phone".

**Premium voice (optional, billed).** `/api/voice/speak` synthesises the assistant's own reply text (≤600 characters, already redacted) through **Sarvam Bulbul** (`bulbul:v3`, Hindi and Indian English, ₹3 per 1,000 characters ≈ ₹1 per answer) or **OpenAI `gpt-4o-mini-tts`** (≈₹1.3 per spoken minute), chosen by `TTS_PROVIDER`, with the secret `TTS_API_KEY` and an explicit `TTS_PAID_CONFIRMED='true'`; Turnstile action `speak`, quota 400/day and 20/minute (bounded worst case ≈₹720/day on Sarvam). Sarvam's base64 WAV is passed through as JSON and decoded in the browser (the Worker's 10 ms CPU budget); OpenAI's MP3 is streamed through with a size cap. The browser plays the first sentence's audio while the rest of the reply is still streaming, fetches the remainder in one batch, unlocks playback inside the consent tap for iOS, and falls back to the browser voice for any failed clip. Unset, nothing changes: browser voices as before. **Founder actions to switch it on:** create a Sarvam account (₹1,000 free credits) or an OpenAI key; `wrangler secret put TTS_API_KEY`; set `TTS_PROVIDER=sarvam` and `TTS_PAID_CONFIRMED=true` as Worker variables; optionally `TTS_VOICE_HI`/`TTS_VOICE_EN` from the provider's voice list. Groq's Developer tier (pay-as-you-go) lifts the chat and speech limits when the free ceilings bind; the quotas in `worker/security.ts` are the single place to raise.
